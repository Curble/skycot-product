# Seam manifest: `apps/nondev` ↔ upstream T3 Code

This fork adds a second browser client for non-developers at `apps/nondev`
(package `@t3tools/nondev`, served at `/simple/`). It is new files only, except
for the touches listed here. CI will enforce that **no other upstream file**
differs from `upstream/main` beyond this list. Keep every entry to the smallest
appended change so rebases stay mechanical.

Reasoning behind each touch is in the architecture report that produced this
plan (section 8, items B-1 to B-5). The desktop entry touch (B-6) is applied as
the `brand-client-entry*` seams in the brand table below.

## Brand seams: co-installable "SKYCOT" desktop shell

`node --import ./nondev/brand/env.cjs …`). Every code seam below reads

absent and each line is a candidate upstream PR. `node nondev/scripts/apply-brand.ts` prints the
full constant → mechanism table and fails if a seam lost its marker, its variable or upstream's

## Advanced mode and command-line seams (24 October 2026)

The brand sweep above left Advanced mode's own screens (`apps/web`, the upstream client SKYCOT opens
as Advanced mode) and the `t3` command-line tool on purpose; Mark then asked that they change too
("Yes replace"). Nothing changes when the variables are absent, so each line stays upstreamable.

- **Advanced mode** reads one constant, `APP_BASE_NAME` in `apps/web/src/branding.ts`: the desktop's
  injected name, else the build's `T3CODE_APP_BASE_NAME` (a Vite `define`, `SKYCOT` from
  `nondev/brand/env.cjs`), else `"T3 Code"`. Each screen file imports it on one line carrying its
  marker. Shared code the web bundle also runs (`packages/client-runtime` connection messages,
  `packages/shared` prompt links, `packages/contracts` copy, OpenCode settings) uses `APP_NAME` from
  `packages/shared/src/appName.ts` (contracts: its own internal `appName.ts`), a guarded
  `process.env.T3CODE_APP_BASE_NAME` read that the web build defines. `apps/nondev`'s own build has
  no such define yet, so these shared messages still say "T3 Code" in the simple client.
- **The command** is `CLI_COMMAND_NAME` (`T3CODE_CLI_NAME ?? "t3"`; env.cjs sets brand.json
  `cliName`, `skycot`) in `packages/shared/src/cliRelease.ts`, beside `CLI_APP_NAME`. The desktop
  installs `<home>/bin/skycot` and links `skycot`, never `t3`; the launcher exports the brand
  variables the app was started with (`apps/desktop/src/skycot/cliCommand.ts`, fork-owned), so the
  CLI's help, usage and errors say SKYCOT and `skycot …`. An older SKYCOT build's own `t3` (its
  link points at `<SKYCOT home>/bin/t3`, which carries upstream's marker and SKYCOT's home) is
  offered for replacement in Settings and removed by Install; any other `t3`, a real T3 Code's
  above all, is never replaced or removed.

Left on purpose: protocol and internal identifiers (routes, storage keys, `t3` npm package
identity in `cli/invocation.ts`, `refs/t3/**`, `T3_*` / `T3CODE_*`), T3 Connect text (off in
